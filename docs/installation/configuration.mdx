# Configurer l'environnement de développement SantéSN

> Clonez le dépôt, créez un environnement virtuel, définissez vos variables d'environnement et lancez SantéSN en local étape par étape.

Cette page vous guide à travers la configuration complète de votre environnement de développement local pour SantéSN. À l'issue de ces étapes, vous disposerez d'une instance fonctionnelle de l'application connectée à votre base de données PostgreSQL locale ou cloud.

<Note>
  Assurez-vous d'avoir suivi la page [Prérequis](/installation/prerequis) et de disposer de Python 3.10+, pip et PostgreSQL avant de commencer.
</Note>

## Mise en place complète

<Steps>
  <Step title="Cloner le dépôt">
    Récupérez le code source de SantéSN depuis le dépôt Git officiel :

    ```bash theme={null}
    git clone https://github.com/votre-organisation/santesn.git
    cd santesn
    ```

    <Note>
      Remplacez `votre-organisation/santesn` par le chemin exact du dépôt qui vous a été communiqué. Contactez votre administrateur si vous ne disposez pas de l'URL.
    </Note>

    Vérifiez que vous êtes bien sur la branche principale :

    ```bash theme={null}
    git branch
    # * main
    ```
  </Step>

  <Step title="Créer un environnement virtuel">
    Créez un environnement virtuel Python isolé pour le projet afin d'éviter tout conflit de dépendances avec d'autres projets sur votre machine.

    ```bash theme={null}
    python -m venv venv
    ```

    Activez-le ensuite selon votre système d'exploitation :

    <Tabs>
      <Tab title="macOS / Linux">
        ```bash theme={null}
        source venv/bin/activate
        ```
      </Tab>

      <Tab title="Windows (PowerShell)">
        ```powershell theme={null}
        .\venv\Scripts\Activate.ps1
        ```
      </Tab>

      <Tab title="Windows (CMD)">
        ```cmd theme={null}
        venv\Scripts\activate.bat
        ```
      </Tab>
    </Tabs>

    Une fois activé, votre invite de commande affiche le préfixe `(venv)`.

    <Tip>
      Pensez à toujours activer votre environnement virtuel avant d'exécuter des commandes `python` ou `manage.py` dans ce projet.
    </Tip>
  </Step>

  <Step title="Installer les dépendances">
    Installez toutes les dépendances Python du projet à partir du fichier `requirements.txt` :

    ```bash theme={null}
    pip install -r requirements.txt
    ```

    Cette commande installe notamment Django, psycopg2 (connecteur PostgreSQL), python-decouple et toutes les autres bibliothèques nécessaires au fonctionnement de SantéSN.

    <Note>
      Si une dépendance échoue à s'installer (par exemple `psycopg2`), vous pouvez utiliser la version binaire : `pip install psycopg2-binary`.
    </Note>
  </Step>

  <Step title="Créer le fichier .env">
    Copiez le fichier d'exemple de configuration et personnalisez-le avec vos propres valeurs :

    ```bash theme={null}
    cp .env.example .env
    ```

    Ouvrez le fichier `.env` dans votre éditeur et renseignez les variables. Voici un exemple complet de fichier `.env` pour un environnement local :

    ```ini theme={null}
    # ─── Sécurité Django ───────────────────────────────────────────────────────
    SECRET_KEY=votre-cle-secrete-django-tres-longue-et-aleatoire
    DEBUG=True

    # ─── Hôtes autorisés ────────────────────────────────────────────────────────
    # En local, laissez localhost et 127.0.0.1.
    # En production, indiquez votre domaine Vercel (ex. : projet-final-bice.vercel.app)
    ALLOWED_HOSTS=localhost,127.0.0.1

    # ─── Base de données PostgreSQL ─────────────────────────────────────────────
    # Option 1 : URL complète (recommandée pour Vercel et services cloud)
    DATABASE_URL=postgres://santesn_user:motdepasse@localhost:5432/santesn_db

    # Option 2 : Variables individuelles (alternative si DATABASE_URL n'est pas utilisé)
    # DB_NAME=santesn_db
    # DB_USER=santesn_user
    # DB_PASSWORD=motdepasse
    # DB_HOST=localhost
    # DB_PORT=5432
    ```

    <Warning>
      Ne commitez jamais votre fichier `.env` dans Git. Vérifiez que `.env` figure bien dans votre `.gitignore` avant tout `git add`. Une fuite de `SECRET_KEY` ou des identifiants PostgreSQL expose la totalité des données de santé de la plateforme.
    </Warning>
  </Step>

  <Step title="Créer la base de données PostgreSQL">
    Avant d'appliquer les migrations, créez la base de données et l'utilisateur PostgreSQL correspondants :

    ```bash theme={null}
    # Connectez-vous à PostgreSQL en tant que superutilisateur
    psql -U postgres
    ```

    Puis exécutez les commandes SQL suivantes dans le shell `psql` :

    ```sql theme={null}
    CREATE DATABASE santesn_db;
    CREATE USER santesn_user WITH PASSWORD 'motdepasse';
    ALTER ROLE santesn_user SET client_encoding TO 'utf8';
    ALTER ROLE santesn_user SET default_transaction_isolation TO 'read committed';
    ALTER ROLE santesn_user SET timezone TO 'Africa/Dakar';
    GRANT ALL PRIVILEGES ON DATABASE santesn_db TO santesn_user;
    \q
    ```

    <Info>
      Si vous utilisez un service cloud (Supabase, Neon, ElephantSQL…), récupérez directement l'URL de connexion fournie par le service et collez-la dans `DATABASE_URL`.
    </Info>
  </Step>

  <Step title="Appliquer les migrations">
    Appliquez les migrations Django pour créer toutes les tables dans votre base de données :

    ```bash theme={null}
    python manage.py migrate
    ```

    Vous verrez une sortie similaire à :

    ```
    Operations to perform:
      Apply all migrations: admin, auth, contenttypes, sessions, ...
    Running migrations:
      Applying contenttypes.0001_initial... OK
      Applying auth.0001_initial... OK
      ...
      Applying santesn.0001_initial... OK
    ```

    <Warning>
      Si la commande échoue avec une erreur de connexion à la base de données, vérifiez que les valeurs `DATABASE_URL` (ou `DB_*`) dans votre `.env` sont correctes et que le service PostgreSQL est bien démarré.
    </Warning>
  </Step>

  <Step title="Créer un super-utilisateur">
    Créez le premier compte administrateur Django qui vous donnera accès à l'interface `/admin/` :

    ```bash theme={null}
    python manage.py createsuperuser
    ```

    L'assistant vous invite à saisir :

    ```
    Email : admin@santesn.sn
    Mot de passe : ••••••••
    Confirmation du mot de passe : ••••••••
    Superuser created successfully.
    ```

    <Note>
      Sur SantéSN, le superutilisateur Django n'est pas automatiquement un *Administrateur métier* de la plateforme. Connectez-vous à `/admin/` pour attribuer les rôles appropriés aux comptes utilisateurs.
    </Note>
  </Step>

  <Step title="Lancer le serveur de développement">
    Démarrez le serveur de développement Django :

    ```bash theme={null}
    python manage.py runserver
    ```

    Vous devriez voir :

    ```
    Watching for file changes with StatReloader
    Performing system checks...

    System check identified no issues (0 silenced).
    Django version 4.x.x, using settings 'config.settings'
    Starting development server at http://127.0.0.1:8000/
    Quit the server with CONTROL-C.
    ```

    <Info>
      Ce point est déduit du comportement de la plateforme et n'a pas été vérifié dans le code source. Le nom du module de settings (`config.settings`) peut différer selon la structure du dépôt qui vous a été fourni.
    </Info>

    Ouvrez votre navigateur et accédez à [http://127.0.0.1:8000/](http://127.0.0.1:8000/) pour voir la page d'accueil de SantéSN.

    <Tip>
      Pour lancer le serveur sur un port différent, utilisez `python manage.py runserver 8080`. Pour le rendre accessible sur votre réseau local, utilisez `python manage.py runserver 0.0.0.0:8000`.
    </Tip>
  </Step>
</Steps>

## Référence des variables d'environnement

<AccordionGroup>
  <Accordion title="Variables de sécurité Django">
    <ParamField path="SECRET_KEY" type="string" required>
      Clé secrète utilisée par Django pour la signature cryptographique des sessions, tokens CSRF et autres opérations de sécurité. Doit être longue (50+ caractères), aléatoire et **unique par environnement**. Ne partagez jamais cette valeur.
    </ParamField>

    <ParamField path="DEBUG" type="boolean" required>
      Mettre à `True` en développement local pour afficher les pages d'erreur détaillées. Mettre **impérativement** à `False` en production pour ne pas exposer d'informations sensibles.
    </ParamField>

    <ParamField path="ALLOWED_HOSTS" type="string" required>
      Liste des noms de domaine ou adresses IP autorisés à servir l'application, séparés par des virgules. En local : `localhost,127.0.0.1`. En production sur Vercel : `projet-final-bice.vercel.app`.
    </ParamField>
  </Accordion>

  <Accordion title="Variables de base de données">
    <ParamField path="DATABASE_URL" type="string">
      URL de connexion PostgreSQL au format `postgres://USER:PASSWORD@HOST:PORT/DBNAME`. Recommandée pour les déploiements Vercel et les services cloud. Si cette variable est définie, les variables `DB_*` individuelles peuvent être ignorées selon la configuration du projet.
    </ParamField>

    <ParamField path="DB_NAME" type="string">
      Nom de la base de données PostgreSQL. Exemple : `santesn_db`.
    </ParamField>

    <ParamField path="DB_USER" type="string">
      Nom de l'utilisateur PostgreSQL ayant accès à la base. Exemple : `santesn_user`.
    </ParamField>

    <ParamField path="DB_PASSWORD" type="string">
      Mot de passe de l'utilisateur PostgreSQL. Utilisez un mot de passe fort en production.
    </ParamField>

    <ParamField path="DB_HOST" type="string">
      Adresse du serveur PostgreSQL. `localhost` pour une instance locale, ou l'URL fournie par votre service cloud.
    </ParamField>

    <ParamField path="DB_PORT" type="string">
      Port d'écoute de PostgreSQL. La valeur par défaut est `5432`.
    </ParamField>
  </Accordion>
</AccordionGroup>

## Pages disponibles en local

Une fois le serveur démarré, les URL suivantes sont accessibles :

| URL                                      | Description                                      |
| ---------------------------------------- | ------------------------------------------------ |
| `http://127.0.0.1:8000/`                 | Page d'accueil publique                          |
| `http://127.0.0.1:8000/connexion/`       | Page de connexion (email + mot de passe)         |
| `http://127.0.0.1:8000/tableau-de-bord/` | Tableau de bord (authentification requise)       |
| `http://127.0.0.1:8000/ordonnances/`     | Liste des ordonnances (authentification requise) |
| `http://127.0.0.1:8000/admin/`           | Interface d'administration Django                |

Vous êtes maintenant prêt à développer et tester SantéSN en local. Consultez la page [Base de données](/installation/base-de-donnees) pour en savoir plus sur la structure des données de l'application.
