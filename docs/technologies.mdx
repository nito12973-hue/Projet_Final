# Pile technique de SantéSN : Django, PostgreSQL Neon, Meta API et Prometheus

> Inventaire complet des technologies de SantéSN : Django 5, PostgreSQL Neon, WhatsApp Cloud API, Prometheus, psutil, PWA Service Worker, TLS 1.3 et conformité CDP Sénégal.

SantéSN est construit sur une pile technologique éprouvée, délibérément centrée sur Django pour la robustesse du backend, la rapidité du développement métier et la rigueur de son modèle de sécurité. Cette page recense chaque technologie utilisée, son rôle dans la plateforme et sa contribution à la haute disponibilité et à la conformité réglementaire.

## Backend & Framework applicatif

<CardGroup cols={2}>
  <Card title="Django (Python 3.12)" icon="python" href="/architecture">
    Framework web principal. Gère la logique métier, le routage URL, l'ORM, les templates HTML et la couche d'authentification. Toute la sécurité applicative (sessions 8h, CSRF, isolation multi-tenant, RBAC) est implémentée via les mécanismes natifs de Django.
  </Card>

  <Card title="PostgreSQL (Neon Serverless)" icon="database" href="/installation/base-de-donnees">
    Base de données relationnelle managée avec autoscaling, haute disponibilité et connectivité SSL forcée. Les transactions ACID garantissent l'atomicité des verrous d'ordonnances et des liquidations de tiers payant.
  </Card>
</CardGroup>

## Notifications & Intégrations Externes

<CardGroup cols={2}>
  <Card title="WhatsApp Cloud API (Meta)" icon="whatsapp" href="/fonctionnalites/notifications-whatsapp">
    Graph API Meta officielle pour l'envoi de messages d'activation, rappels de rendez-vous et alertes d'ordonnances. Intègre un webhook bi-directionnel avec vérification de signature cryptographique **HMAC SHA-256**.
  </Card>

  <Card title="QR Code Cryptographique" icon="qrcode" href="/fonctionnalites/ordonnances">
    Génération à la volée de QR codes vectoriels pour les cartes d'assurés et les ordonnances médicales (`RX-XXXXXXXXXX`). Permet la validation instantanée par scan optique déconnecté ou connecté.
  </Card>
</CardGroup>

## Observabilité & Supervision

<CardGroup cols={2}>
  <Card title="Exportateur Métriques Prometheus" icon="chart-line" href="/technique/supervision-observabilite">
    Endpoint standardisé `/metrics/` exposant la latence des requêtes, le volume d'appels HTTP par code de retour, la disponibilité de la base de données et les compteurs métier pour ingestion Grafana.
  </Card>

  <Card title="Sondes Matérielles psutil" icon="microchip" href="/technique/supervision-observabilite">
    Bibliothèque d'analyse système inspectant en temps réel la charge CPU, la consommation de mémoire vive RAM et l'utilisation du stockage disque sur le tableau de bord `/supervision/`.
  </Card>

  <Card title="Sentry SDK" icon="bug" href="/technique/supervision-observabilite">
    Capture automatisée des exceptions serveur, alertes temps réel sur incident et corrélation des traces de performance applicative avec déclencheur de test contrôlé.
  </Card>

  <Card title="Registre d'Intégrité SHA-256" icon="fingerprint" href="/technique/supervision-observabilite">
    Mécanisme d'empreinte cryptographique consignant dans `backups/manifest.json` le hachage SHA-256 de chaque sauvegarde de base de données pour détecter toute corruption ou altération.
  </Card>
</CardGroup>

## Authentification et sécurité des données

<CardGroup cols={2}>
  <Card title="Sessions Django (8 heures)" icon="clock" href="/technique/securite">
    L'authentification repose sur les sessions natives de Django. Le cookie `sessionid` est protégé par `HttpOnly` et `SameSite=Lax`. L'expiration automatique intervient après 8 heures d'inactivité.
  </Card>

  <Card title="PBKDF2-SHA256" icon="key" href="/fonctionnalites/authentification">
    Les mots de passe sont hachés avec l'algorithme PBKDF2 associé à un sel cryptographique individuel unique par compte. Aucun mot de passe n'est jamais consigné en clair.
  </Card>

  <Card title="Isolation Multi-Tenant à l'ORM" icon="shield-halved" href="/fonctionnalites/organismes-multi-tenant">
    Cloisonnement logique étanche des données d'organismes (`filter(organisme=request.user.organisme)`). Les assurés et gestionnaires d'une entreprise A ne peuvent jamais accéder aux données d'une entreprise B.
  </Card>

  <Card title="Journal d'Activité Immuable" icon="scroll" href="/architecture">
    Modèle `JournalActivite` en écriture seule (Append-Only) enregistrant chaque consultation, délivrance, connexion et modification administrative conformément aux prescriptions de la CDP.
  </Card>
</CardGroup>
